# Aegis DApp 代码注释规范

> 执行用参照规范（v1）。说明文字一律中文；代码标识符保持英文。只改注释，禁改业务逻辑。

## 1. 分层

| 层级       | 范围                                                                                                                                                                     | 要求                                                                           |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| **严格层** | `src/shared/components/**`、`src/views/**`（**排除** `src/views/dapp/host/**`）                                                                                          | 通俗、简短：页面总览、区块说明、组件用法、行内最小化，彻底去黑话               |
| **逻辑层** | `src/core/**`、`src/web3/**`、`src/hooks/**`、`src/stores/**`、`src/boot/**`、`src/views/dapp/host/**`、`src/shared/lib/**`、`src/shared/config/**`、`src/shared/api/**` | 跟随手册/API 文档，注释写详细（四要素 + `@see` 引用）；统一格式、去 Figma 引用 |
| **豁免**   | `src/i18n/**`、`src/shared/styles/tokens/**`（生成文件）、测试文件                                                                                                       | 不适用                                                                         |

## 2. 注释类型与何时写

| 类型                     | 位置                  | 何时写 | 用途                               |
| ------------------------ | --------------------- | ------ | ---------------------------------- |
| **页面总览** Page banner | 页面文件顶部          | 必写   | 页面定位、主要交互、特殊状态       |
| **区块说明** Block       | 页面/组件内重要区块前 | 酌情   | 该区块用途与交互                   |
| **组件用法** Component   | 非平凡组件上方        | 必写   | 作用、关键 props 语义、何时用/避免 |
| **函数说明** Function    | 非平凡函数上方        | 必写   | 作用、参数、返回值                 |
| **行内注释** Inline      | 代码内                | 最小化 | 只写「为什么」，不写「是什么」     |

密度基准：导出组件与非平凡函数必写 docblock；三五行内一眼可懂、无副作用的简单组件/函数不写。

## 3. 模板与正反例

### 页面总览（顶部 docblock）

首行定位 → 空行 → 主要区块/交互 → 特殊状态。

```tsx
/**
 * 兑换中心页
 *
 * 汇总闪电兑换、市价交易、销毁、Turbine 四种模式的入口，
 * 顶部 Tab 切换当前模式，正文随之切换。
 * 未连接钱包时展示引导卡片，连接后可立即交易。
 */
```

✗ `// 兑换 Hub`（无内容）｜`/** Figma 4430:220 hub */`（节点引用）｜`/** 兑换页 outline chrome SSOT */`（黑话）

### 组件 / 函数 docblock

一句话用途 → 空行 → 补充说明 → `@param` / `@returns`（与签名一致）。

```tsx
/**
 * 兑换数量输入框
 *
 * 超出可用余额时自动校正输入，
 * 并在顶部显示余额上限提示与「最大」按钮。
 *
 * @param value 当前输入数量
 * @param onChange 数量变化时回调
 */
```

✗ `/** 返回 value */`（照抄代码）｜`/** chrome SSOT */`（黑话）｜`/** 见 Figma 4273:242 */`（引用）

### 区块说明

```tsx
// 行情展示区：四币实时价格与涨跌，2 秒刷新
<section>
```

### 行内注释（只写为什么）

```ts
// 后端在余额不足时返回 0，这里兜底成 1，避免除零
const rate = (balance || 1) / total
```

## 4. 文案原则

1. 说明文字全中文；组件名 / props / 类型 / 变量保持英文。
2. 删除所有 `Figma <节点>`、`稿 / 稿面` 节点坐标注释。`/assets/figma/...` 是资产路径本身，**不动**。
3. 严格层禁止黑话词表 7 中的词；逻辑层说明文字也用通俗词，但**保留必要的技术名词**（rebase、vesting、bond、quote 等，用中文说明其含义）。
4. 长度：一句到三句，禁止段落式长文。
5. 陈述句；不自造缩写；不写「XX 函数」「XX 组件」冗余前缀；不重复代码已表达的意思。
6. **禁止满仓统一句式**：同一套措辞反复出现即 AI 腔。避免「前置校验」「fail-closed」「便于 UI 展示」「诚实文案」「可提交时返回 null」这类通用收尾，表达要贴具体场景与具体动机。

## 5. 逻辑层详细规范

核心函数/模块 docblock 至少覆盖四要素：

1. **做什么** — 一句话定位
2. **为什么这么判断** — 业务规则或边界动机
3. **关键语义** — 参数含义、返回值契约（未知/未加载 → null）、fail-closed 行为
4. **文档对应** — `@see` 指向手册章节或 API 文档

`@see` 引用统一格式（废除 `Handbook` / `manual` / `Pre-Design` 旧式写法）：

| 指向     | 格式                                             |
| -------- | ------------------------------------------------ |
| 手册章节 | `@see 手册 §X.Y 标题`                            |
| 合约文档 | `@see docs/onchain-manual/contracts/<name>.md`   |
| API 端点 | `@see docs/backend-api/api.md #<tag>/<endpoint>` |
| 组件文档 | `@see docs/foundation/component-usage.md`        |

示例：

```ts
/**
 * 解除质押是否需要推荐人
 *
 * 手册 §5 规定：未绑定推荐关系的地址，
 * 在质押 / 债券 / 治理写操作前必须补绑，否则前端禁写。
 * 本函数只在「已连接钱包」路径被调用。
 *
 * @param address 待检查的钱包地址
 * @returns 需要推荐人时返回 true；已绑定或未连接返回 false
 * @see 手册 §5 推荐关系 Referral
 */
```

## 6. IDE 与格式要求

- 全部 docblock 用 `/** */` JSDoc 格式，VS Code 悬浮即显示。
- 分层范围内导出组件/函数必带 docblock。
- `@param` 名称必须与函数签名参数名完全一致。

## 8. 反模式（严格层 docblock 易踩的坑）

1. **不写实现说明书**：间距值、字阶、动画实现、内部子组件名、token 表达式都是实现细节，删。
   ✗ 「节间距由外层 Detail 承担（桌面 34 / 移动 24）；节内统一 gap-4。标题字阶走 Text variant='section'，进场带 reveal 动画，折叠箭头用 CollapseChevron。」
   ✓ 「右栏内容节，含标题与说明。可折叠：点击标题收起 / 展开正文。」
2. **不复述签名**：`@returns 可提交时返回 null` 与签名 `... | null` 重复，删。
   ✗ 「依次校验 A/B/C → 返回 null。@returns 阻断原因；可提交时返回 null。」
   ✓ 只写 A/B/C 各在什么**业务条件**下成立、为什么这样限制（费率 / 防误操作 / 上游未就绪）。
3. **不写通用套话**：「便于 UI 展示」「诚实文案」「fail-closed 保护」若无具体内容，删。
4. **逻辑层也要动机**：四要素里的「为什么」要写约束来源（手册条款 / 合约行为 / 用户误操作风险），不是复述判断条件。
