## 两张表怎么读

| 表                             | 记什么                                                                                           | 不记什么                                                    |
| ------------------------------ | ------------------------------------------------------------------------------------------------ | ----------------------------------------------------------- |
| **A. 手册 / API / 链能力缺口** | 未提供、提供错误、手册↔API 打架、同文档自相矛盾；**以及「要修好必须链上/API 先给能力或改字段」** | 「请上游改文档」执行单正文；纯前端可独立修的接错            |
| **B. 前端可独立修复**          | **不依赖**新 API、新链上能力、上游改文档即可合入的 FE 修复（接错、文案、读源、翻页、入口误导等） | 故意空态 `0`/`—`；须等 API/链配合才能做完的项（那些进表 A） |

同一主题可拆两行：能力缺口 → **A**；前端在现有能力下仍接错/误导 → **B**。  
例：卖 X 路径不存在 → **A-02**；卡片却写成可卖、点进去骗进 USD1 → **B-03**（只修入口/文案，不宣称已接通卖 X）。

**编号约定：** `A-01`… / `B-01`… 稳定引用。新增接续最大号；**勿复用已关闭编号**（行内可标 `关闭`）。

**B 表准入（硬规则）：** 问「现在就能开 PR 只改本仓前端合进去吗？」→ 能则进 B；不能（要等后端字段 / 新交易路径 / 产品先定且 FE 无安全临时态）→ 进 A 或下文「阻塞·待产品」，**不进 B**。

**表列含义：** `问题描述` = 出了什么事（普通人能懂）；`造成的结果` = 对用户/对账/交易的影响；B 另有 `如何对齐` = 只改前端怎么修。
